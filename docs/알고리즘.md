# 트럭 승하차 계단 이용 판정 알고리즘

단일 고정 카메라(측면 부감) 영상에서, 작업자가 트럭 적재함에 오르내릴 때 지정 계단을 사용했는지 판정한다.
다른 현장·카메라·모델에 이식 가능하도록 입력·상태·규칙·파라미터를 구현과 분리해 적는다. 참조 구현: `stair_check.py` (Python, ultralytics + OpenCV).

---

## 1. 입력

| 항목 | 내용 |
|---|---|
| 영상 | 고정 카메라, 20 fps 기준 (파라미터는 초 단위라 fps 무관) |
| 검출기 | 3클래스: `person`, `truck`, `stairs`. 여기선 yolo26m 파인튜닝(imgsz 1280) |
| 트래커 | ByteTrack (ultralytics `model.track(persist=True)`) — person id 필요 |
| 프레임당 얻는 것 | person 박스+id, truck 박스, stairs 박스 |

검출기·트래커는 교체 가능. 아래 로직은 박스와 id만 쓴다.

---

## 2. 프레임당 기하 구성

### 2.1 트럭
- `truck` = 폭 300px 이상인 truck 박스 중 최대 면적 1개
- 트럭 없으면: 판정 안 함. 2초 이상 없으면 검출을 `idle_stride`(10)프레임에 1회로 줄임

### 2.2 계단
- 트럭 x범위 ±20% 안에 중심이 있는 stairs 박스 중 최고 신뢰도 1개
- 검출되면 **트럭 상대좌표**(x,y 를 트럭 폭·높이로 정규화)로 캐시
- 미검출 시 캐시로 복원, 15초까지. 그 뒤엔 "계단 없음"

### 2.3 데크선 (적재함 바닥 높이 선)  `bed_y(x)`
"트럭 위"의 아래 경계. 세 요소를 합친다.

1. **앵커 높이**: 계단 상단 y (`stairs.y1`), 계단 없으면 `truck.y1 + 0.40·th` (th = 트럭 박스 높이)
2. **기울기**: 트럭 박스 높이 30~80% 대역에서 Canny+HoughLinesP 로 가장 긴 준수평(|기울기|≤0.30) 직선 = 화물 밑면/옆판 윗선. 5프레임마다 갱신, EMA 0.9. 트레일러가 화면에서 비스듬해 반드시 필요(수평선이면 앞단 사람이 지면으로 찍힘). 엣지 없으면 데크 위 사람 발끝으로 최소자승 학습(±0.12 제한)
3. **구간 보정**: 트럭 폭 12구간, 구간별로 데크 위 사람 발끝 높이(앵커 대비) 지수평균. 표본 5개 이상인 구간만 사용, 직선 대비 ±0.15·th 로 제한. 계단이 실제 검출된 상태에서만 학습

```
straight(x) = anchor_y + slope · (x − anchor_x)
bed_y(x)    = clip( interp(bins)(x), straight(x) ± 0.15·th )   # 구간 표본 있으면
            = straight(x)                                        # 없으면
```

학습값(slope, bins)은 파일로 저장해 재사용 가능(`bed_profile.json`). 카메라 고정이면 영상마다 학습 불필요.

### 2.4 작업영역 (빨강)
```
x : truck.x1 ~ truck.x2, 단 계단 반대편 끝 15% 제외 (캡)
y : truck.y1 − 0.20·th  ~  bed_y(x) + band
band = 0.20·th (진입) / 0.22·th (유지, 히스테리시스 0.02)
```
아래쪽 여유 20%가 핵심: 적재함 바닥은 계단 상단보다 낮고, 화물 더미↔바닥 이동을 승하차로 오판하지 않게 한다. 진짜 지면은 트럭 박스 바닥(바퀴) 근처(+50%)라 안 섞임.

### 2.5 계단 게이트 (초록)
계단 박스를 좌우 1.0배(폭 기준), 위 0.08·th, 아래 0.08·th 확장. 더 키우면 계단 옆 지면 사람이 "계단"으로 잡힘.

---

## 3. 사람별 상태

발끝 = 박스 하단 중앙 `(cx, y2)`. 키비율 `r = 사람높이 / th`.

```
if 발끝 ∈ 게이트 and r ≥ 0.18            → STAIR
elif r < 0.22 or r > 0.75                 → None   (가림·원거리: 관측 무효, 상태 유지)
elif 발끝 ∈ 작업영역                       → DECK
elif 발끝이 데크 높이(y ≤ bed_y+band)       → None   (트럭 뒤·화물 돌출부: 트럭 위도 지면도 아님)
else                                       → GROUND (발끝이 빨강 아래 = 지면)
```

핵심 원칙: **"내려옴"은 발끝이 빨강 아래로 간 것뿐.** 옆으로 벗어나는 건 하차가 아니다(허공에 못 떠 있음). 이 한 줄이 "트럭 뒤로 갔다 옴" 오판을 막는다.

상태 확정: 같은 후보가 5프레임 연속이면 확정(디바운스). `None`은 카운트에 안 들어감.

---

## 4. 이벤트

```
GROUND → DECK  확정  : UP  (승차) 후보
DECK   → GROUND 확정 : DOWN(하차) 후보
STAIR  → DECK / GROUND 도 동일 (계단에서 온 경우, 자동 OK)
```

조건:
- 직전 상태가 1초 이상 지속됐어야 함 (`min_dwell`) — 새 트랙이 튀는 것 방지
- 후보는 **3초 유지**(`settle`) 후 확정. 그 안에 상태가 되돌아가면 취소

판정:
```
used = 계단 접촉 시각 ≥ max(직전 상태 확정 시각, 전이 − 6초)
```
- `used` → **OK**
- 아니고 계단 검출 있음 → **NO_STAIRS**
- 계단 검출 없음 → **UNVERIFIABLE** (옵션 `no_stairs_alarm` 이면 NO_STAIRS)

**계단 접촉** = 발끝 점이 게이트 안에 찍힘 **또는** 연속 발끝 점을 이은 선분이 게이트를 가로지름(Liang-Barsky). 후자가 빠른 등반·검출 누락을 보완.
**순서 조건** = 계단 접촉이 직전 상태 확정 이후여야 함. 지면→계단→트럭 순서. 계단 밟고 지면으로 돌아간 뒤 옆으로 오르면 위반.

## 5. 트랙 안정화 (없으면 오알람 폭주)

| 문제 | 처리 |
|---|---|
| 트래커 ID 교체(가림) | 새 트랙 첫 발끝이 2초 내 사라진 트랙 마지막 발끝과 120px 이내·수직 25px 이내면 상태 상속. 유효 관측 5프레임 미만 유령 트랙은 상속 불가 |
| 두 사람 사이 ID 스왑 | 발끝이 프레임당 90px 이상 순간이동하면 이력 리셋 |
| 박스 병합/분리 | 발끝 25px 이상 또는 키비율 0.12 이상 급변(3프레임 내)이면 그 프레임 관측 무효 |
| 트랙이 트럭 위에서 생성 | 앵커 없음 → 이벤트 안 냄 ("출처 불명"). 이 경우 승차는 못 잡음(구조적 미탐) |

## 6. 파라미터 (트럭높이 th, 트럭폭 tw 단위)

| 이름 | 값 | 의미 |
|---|---|---|
| debounce | 5 프레임 | 상태 확정 |
| min_dwell_s | 1.0 | 직전 상태 최소 지속 |
| settle_s | 3.0 | 이벤트 확정 대기 |
| lookback_s | 6.0 | 계단 접촉 유효 시간 |
| stairs_ttl_s | 15 | 계단 캐시 수명 |
| h_ratio | 0.22 ~ 0.75 | 유효 사람 키비율 |
| stair_ratio | 0.18 | 계단 판정 최소 키비율 |
| deck_band / hyst | 0.20 / 0.02 | 빨강 아래 여유 |
| top_margin | 0.20 | 빨강 위 여유 (화물 위) |
| cab_frac | 0.15 | 캡 제외 비율 |
| gate_wx / gate_hy / gate_up | 1.0 / 0.08 / 0.08 | 게이트 확장 |
| inherit_s / inherit_px / inherit_dy | 2.0 / 120 / 25 | ID 교체 상속 |
| jump_px | 90 | 순간이동 리셋 |
| step_px / step_ratio | 25 / 0.12 | 박스 급변 무효 |
| idle_stride | 10 | 트럭 없을 때 검출 간격 |

실측 근거(2026-09-10 카메라1): 트럭 위 사람 발끝은 데크선 대비 −0.05~+0.21 (중앙값 0.15), 화물 더미 위 0.31~0.41. 키비율 트럭 위 0.25~0.38. 데크선 기울기 −0.11~−0.16.

## 7. 검증 결과 (동일 카메라, 13분 분량)

- 계단 사용 12건 전부 OK, 계단 없이 하차 1건 NO_STAIRS, 오알람 0
- 미탐 1건: 캡 쪽 가림으로 사람이 처음부터 트럭 위에서 잡힌 케이스
- 위반 양성 표본이 2건뿐 — 재현율은 미확정

---

## 8. 다른 현장에 옮길 때

1. 3클래스 검출기 재학습 (person / truck / stairs). 계단은 오픈보캐뷸러리(YOLO-World "step ladder")로 프리라벨 가능
2. 카메라 각도가 바뀌면 6절 실측값부터 다시 뽑기: 트럭 위 사람 발끝의 데크선 대비 분포, 키비율 분포
3. 캡 위치·계단 위치가 반대면 자동 처리됨(캡 = 계단 반대편)
4. 트럭 2대 동시 정차는 미지원(최대 박스 1개만)
5. 실시간이면 한글 오버레이(PIL) 끄기 — 37→15 fps 로 떨어짐

## 9. 알려진 한계

- 트럭 뒤 지면과 적재함 바닥이 화면 y에서 겹치는 각도에서는 구분 불가 → "모름"으로 처리해 알람은 안 나가지만 판정도 안 남
- 트랙이 트럭 위에서 생성되면 승차를 못 잡음. 해법은 등반 자세 인식(포즈) 또는 두 번째 카메라
- 위반 알람은 전이 후 3초 지연
